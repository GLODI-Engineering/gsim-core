## 2026-09-04 10:04 — 4 more fixtures for `general-simulator`'s newest commits

The user updated `general-simulator` since Phase 1 completed (six new commits,
2026-08-31..09-04); read all of them to stay current. Two were directly relevant to
`gsim-core`:

- **`general-mna` renamed `Sig2Voltage`/`Sig2Current` -> `Sig2Phys{domain}`, `Probe` ->
  `Phys2Sig`** (commit `9c02d80`, consumed here). Confirmed `gsim-core` never referenced the old
  names anywhere committed, so nothing needed correcting. The rename itself validates a design
  choice already made here: `Sig2Phys`/`Phys2Sig` are exactly instances of the GUI's
  `paradigm: converter` concept (`docs/specs/gsim-sch-format.md` §8's `physical-signal` port
  kind, bridging acausal physical-network and causal signal-flow) that `Paradigm::bridges_paradigms()`
  already models in `document::builder`.
- **`kind=octfunc`/`kind=octblock`** (commits `2f0352b`, `e6a13cb`) — new Octave-hosted script
  block kinds, called via a persistent `octave-cli` subprocess (deliberately never linked
  in-process, to keep this MIT project clear of GPLv3 Octave). A genuinely new component family:
  open-arity `inputs=`/`outputs=` rather than a fixed parameter set.

Added 4 more real fixtures, each proving something the first 8 didn't cover:

- `converter.sig2phys` — a `paradigm: converter` component with a `domain: voltage|current`
  enum param, bridging a `signal` port to a `physical-electrical` port.
- `converter.phys2sig` — **zero input ports** (matches the real component exactly: "Zero
  block-graph inputs, it reads the circuit's own previous-step operating point directly") — the
  first fixture with an empty `ports:` list — plus a real mutually-exclusive-parameter rule
  (`node` XOR `branch`, `${{ (value != '') != (params.branch != '') }}`), the first
  cross-parameter validation testing something other than an ordering constraint.
- `extensibility.octfunc` / `extensibility.octblock` — **two independent variadic port groups
  in one component** (`input_names` and `output_names` each drive their own `for_each`,
  unrelated in length/content) — not exercised by any of the first 8, which each had at most one
  variadic group. `octblock` adds a validated `xc_count >= 0` integer param on top of the same
  port shape.

All 4 passed on first run, no new bugs found this time (the closed builtin whitelist and
cross-parameter defaulting fix from the previous session's authoring already covered everything
these needed).

--all-targets -- -D warnings`, `cargo fmt --all -- --check` — all clean.
